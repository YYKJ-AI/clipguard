# 开源选型与节省工时方案

日期：2026-11-10。范围：针对性 GitHub 调研与实现选型，未开始产品编码。已补充核查 Bifrost 的职责，撤回将其作为默认接入路径的决定。

## 结论

首版网页候选方案为 Go 标准库提供 HTTP 接口，并使用 embed 携带 HTML、CSS 和浏览器原生 JavaScript 页面；运行 Go 程序后在浏览器访问。模型接入取决于领导最终提供的接口，不预先要求 Bifrost，也不把本机已有网关等同于项目依赖。

模型接入决策：如果提供的模型服务可直接调用，优先直连；如果提供的是已配置网关地址，就调用该地址；只有实际存在协议转换、多供应商管理等需求，且收益大于额外启动、配置及排错成本时，才考虑新增 Bifrost。验收者不应为了启动本项目而被默认要求安装它。

当前不选完整剪辑器、Agent 模板、React 聊天框架或可拖拽时间轴组件作为主体。不强制 npm 安装、前端构建或在线 CDN。离线路径的网页资源随仓库提供。

这是根据首版交互范围作出的工程选择，不表示相关开源组件质量不佳，也不代表未来不能采用。选型仍需在实际实现时验证接口与交互效果。

## Bifrost 的职责及本项目是否需要它

Bifrost 是模型 API 网关／协议适配层：应用把请求发给它，它使用已配置的上游服务与凭据转发请求，处理协议转换，并可提供路由、重试、限流、虚拟密钥、日志和预算管理等能力。具体功能仍取决于版本和配置。

它本身不是大模型，也不因下载或启动就自动获得推理能力、密钥或额度；它不能替我们完成剪辑意图业务定义、时间轴校验、用户确认或撤销。其自带管理页面用于配置模型服务，不是本项目的剪辑交互页面。

两条可行路径：

- 直接调用：本项目 Go 后端 → 领导提供的模型服务。
- 经网关调用：本项目 Go 后端 → 已配置 Bifrost → 上游模型服务。

目前需求只要求模型理解、澄清和生成候选计划，没有多供应商治理等明确需求，因此不足以证明新增网关能节省时间。原先因用户本机已有文件就将其放进默认路径的判断已撤回。

证据来自本地仓库 docs/quickstart/gateway/setting-up.mdx、provider-configuration.mdx、docs/features/drop-in-replacement.mdx、docs/features/governance/virtual-keys.mdx，以及 transports/bifrost-http/integrations/openai.go 路由定义。文档与源码检查不代表已测试实际调用。

## 为什么此时少引入组件更省时

- 首版页面职责有限：导入、片段展示、对话、候选选择、差异预览、确认／取消、撤销、导出。
- 核心工作是 Go 引擎中的事务、版本与校验；完整剪辑框架不能替代这些任务要求。
- Go 同时提供页面与接口，只维护一个启动进程和一个访问地址，避免前后端开发服务器、跨域与构建链配置。
- 标准 HTTP 客户端仅封装本项目实际使用的模型接口，不自行开发通用 SDK。
- 复用收益若在实现中发生变化，可以引入单个必要依赖；不预先维护大型框架。

## 本地运行方案

更新：用户已确认几十人各自编辑自己的工程。需支持独立会话，并可通过启动参数启用局域网访问。下面的本机流程仍适用于单机测试；多用户架构、资源控制和新增验收以《多用户独立工程补充方案》为准，原 17—19 小时估算不再覆盖新增范围。

1. 启动 Go 程序，默认只监听本机回环地址。
2. 浏览器打开程序给出的本地地址。
3. 导入工程，查看轨道及片段。
4. 在页面发送消息；模型模式支持自由表达，离线模式使用公开句式。
5. 页面展示澄清选项或变更预览；用户确认后 Go 执行。
6. 可连续撤销本次程序运行中的提交；点击导出下载当前工程 JSON。

不要求服务器部署、域名或公网访问。计划以 go run 和 go build 为主要启动、构建路径，实际命令待工程建立后验证。若采用标准库方案，本项目本身不要求前端包管理器。

## 模型接入控制范围

- 配置接口地址、模型标识、认证及超时，密钥不进入浏览器或仓库。
- 先实现可替换解析接口、模拟服务测试和离线中文路径；模型到位后做真实调用验证。
- 初步以兼容 Chat Completions 的非流式 HTTP 请求为窄适配候选，最终协议以领导提供的接口为准。
- 若接口支持结构化输出则使用；否则验证完整 JSON 回复，不把随意截取的模型文字当作可信计划。
- 模型只返回候选操作、澄清需求或不支持；Go 严格验证未知操作、额外字段、目标和参数。
- 模型超时、认证失败、输出错误和业务校验拒绝分别报告，失败不改变工程。
- 首版不做流式工具调用、自动模型路由、长期记忆、联网搜索或通用工具执行。

## 节省时间的顺序

1. 固定请求／响应契约，用验收场景写核心行为测试。
2. 实现 Go 编辑引擎和快照撤销，在无模型情况下验证正确性。
3. 接最小 HTTP 接口和页面，用模拟响应串联预览确认。
4. 加离线解析和模型适配器，模型就绪后验证自由表达与澄清。
5. 运行完整回归并完成 README、依赖说明和两页以内设计说明。

不因省时而省略四类操作、原子性、明确确认、过期防护、撤销或负例测试。17—19 小时仍是前期粗估，组件调研结果不构成工期保证。
