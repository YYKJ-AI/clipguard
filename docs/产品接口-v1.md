# 产品接口 v1：独立模块对接契约

更新：2026-11-11。接口实现已完成，并以独立程序及真实 HTTP 验证。实际 ToC 产品的工程格式和身份方式尚未确定，因此当前交付包含版本化接口、参考身份适配器和工程格式扩展点；不将其标记为真实产品联调完成。

## 1. 职责与运行方式

- 模块负责：校验调用身份、按用户及工程隔离状态、解析指令、预览、明确确认、原子编辑、版本保护、撤销及 JSON 导入导出。
- 调用方负责：业务登录流程、用户生命周期、确定实际工程格式，以及将导出的结果保存到自己的工程存储。模块当前仍采用已约定的进程内存状态；成功响应表示运行中状态已更新，不代表已持久化到磁盘或产品数据库。
- 默认地址 `http://127.0.0.1:8090`，基础路径 `/api/v1`。`LISTEN_ADDR` 仍可覆盖。产品服务端到服务端调用使用 Authorization 凭据，跨主机调用应由产品基础设施提供 HTTPS。
- 产品接口未配置身份校验时返回 `503 INTEGRATION_DISABLED`。启用产品身份配置后，匿名旧 `/api/*` 浏览器接口关闭，避免通过旧消息入口绕过产品身份边界。内置网页适用于未启用产品身份的本地开发模式。
- 机器可读定义：[OpenAPI](openapi.json)、[timeline.v1 JSON Schema](timeline.schema.json)。API 主版本在 URL；本次不提供自动跨版本转换。

## 2. 身份与工程归属

身份来自 `Authenticator.Authenticate(request)` 的校验结果，工程使用 `(已验证用户标识, project_id)` 定位。请求 JSON 中自报的 `user_id`、`owner_id` 等额外字段会被拒绝；`X-User-ID` 不参与归属判断。浏览器 Cookie 也不是产品身份。

两个用户可拥有相同工程 ID、版本及片段 ID，状态仍独立。其他用户的同名计划不能确认或取消。工程不存在和不属于当前用户都返回 `404 PROJECT_NOT_FOUND`，不泄露他人工程是否存在。对他人或已失效计划统一返回 `409 STATE_CONFLICT`。

参考身份适配器通过 `PRODUCT_AUTH_FILE` 加载凭据映射，文件形状如下；这里只展示结构，凭据必须由调用方生成并保密：

```json
{
  "credentials": [
    {"subject": "stable-product-user-id", "token": "<32 至 256 个字符的随机凭据>"}
  ]
}
```

使用密码学随机源生成凭据，不使用用户 ID、示例字符串或短密码。文件不得提交仓库。程序拒绝空配置、重复凭据、过短凭据和未知字段；内存中仅保留凭据摘要到用户标识的映射。启动日志不输出凭据。

```powershell
$env:PRODUCT_AUTH_FILE='C:\your-private-config\product-auth.json'
go run .
```

请求携带 `Authorization: Bearer <该用户的凭据>`。多个浏览器或后端实例使用同一已验证用户标识可访问同一运行中工程，不依赖临时 Cookie。参考适配器是明确配置的静态凭据机制，没有登录、令牌交换、有效期或在线撤销服务；修改映射后需重启。真实产品令牌、过期和撤销规则确定后，通过 `Config.ProductAuth` 实现对应校验，不能把未验证的 JWT 内容当作用户身份。

参考凭据适用于可信产品后端对接；不能把一个共享后端凭据下发给多个终端用户。没有实现跨站 CORS 开放。产品前端可由自己的后端代理调用并保留原有登录体验。

## 3. 工程格式与读写契约

默认格式是 `timeline.v1`，结构与 `examples/timeline.json` 一致。未知字段严格拒绝，不会静默丢弃产品额外字段、素材引用或编辑元数据。Schema 描述字段结构；唯一 ID、引用存在性、锁轨、同轨重叠、素材区间、UTF-8 字节长度和整数溢出仍由 Go 校验。

所有时间为整数毫秒。Go 使用 int64；使用 JavaScript 的调用方必须避免超出安全整数范围的数值被自动舍入，必要时在工程适配层使用精确整数解析并校验可表达范围。

`ProjectCodec` 扩展点：

```go
type ProjectCodec interface {
    Name() string
    Decode([]byte) (Project, error)
    Encode(Project) ([]byte, error)
}
```

通过 `Config.ProjectCodec` 接入产品格式。Decode 用于加载工程，Encode 仅用于导出；Go 在 Decode 后再次独立验证。读取和修改响应始终返回规范化 `timeline.v1`，预览差异也使用规范化字段。`source_format` 表示当前导入导出适配器的格式名称。

真实格式未提供前，不实现假想剪辑器适配。后续适配必须定义时间换算、素材 ID、轨道锁定和未知元数据保留规则，并使用真实格式样本验证导入→编辑→导出；当前测试中的包裹格式只证明扩展点可替换，不证明真实产品兼容。

## 4. API 列表

所有接口均需产品身份；除 GET 外使用 `Content-Type: application/json`。请求体最多 1 MiB。路径中的 ID 需要 URL 编码，但不允许用斜杠构造路径层级。

| 方法 | 路径（省略 `/api/v1`） | 请求 | 成功结果 |
|---|---|---|---|
| PUT | `/projects/{id}` | 原始工程 JSON；创建使用 `If-None-Match: *` | 201；规范化 project、format、source_format，响应 ETag |
| GET | `/projects/{id}` | 无 | 200；规范化 project、format、source_format，响应 ETag |
| PUT | `/projects/{id}` | 工程 JSON；替换使用 `If-Match: <GET 返回的完整 ETag>` | 200；替换后的工程及新 ETag |
| GET | `/projects/{id}/export` | 无 | 200；适配器输出的原始工程 JSON 下载，响应 ETag |
| POST | `/projects/{id}/messages` | `{"mode":"offline","text":"把 clip-a 缩短 1 秒"}` | 200；answer、plan、clarify 或 unsupported，尚不提交 |
| POST | `/projects/{id}/plans/{planId}/confirm` | `{}` | 200；project、实际 changes、message |
| POST | `/projects/{id}/plans/{planId}/cancel` | `{}` | 200；取消说明，不修改工程 |
| POST | `/projects/{id}/undo` | `{"request_id":"调用方生成的唯一请求标识"}` | 200；恢复后的 project、实际 changes、message |

用户选择候选时向 messages 发送 `{"mode":"offline","choice":"clip-b","clarification_id":"上次返回的标识"}`。模型模式将 mode 改为 model；尚未配置模型时会明确拒绝。

模型按角色判断剪辑咨询、编辑需求与无关闲聊。`answer` 仅返回 `status` 和 `message`，不包含操作、预览或候选，不产生版本及撤销记录；闲聊返回 `unsupported` 及简短引导，不附加离线句式模板。产品接口仍要求已存在且属于当前身份的工程。

结构化计划的 `trim` 支持两种互斥字段：`duration_ms` 为最终总时长（保留兼容），`shorten_by_ms` 为要缩短的正整数毫秒。必须且只能提供一个；后者由 Go 按组合操作的工作状态逐项相减，结果必须大于零。其他操作不得携带 `shorten_by_ms`。此字段仅在操作计划中使用，不加入工程片段格式。

预览返回示意：

```json
{
  "status": "plan",
  "message": "请检查实际变更，确认后才会修改工程",
  "preview": {
    "id": "opaque-plan-id",
    "project_id": "rough-cut-demo",
    "revision": 1,
    "operations": [{"type":"trim","target_id":"clip-a","duration_ms":4000}],
    "changes": [{"id":"clip-a","before":{},"after":{}}]
  }
}
```

上例 before/after 省略了完整片段字段；实际接口返回完整片段快照，删除后的 after 为 null。

## 5. 条件写入、版本与重试

- 创建工程需要 `If-None-Match: *`；已存在时返回 412，不会覆盖。
- 替换工程必须先 GET，携带其完整、含双引号的 ETag 作为 If-Match。缺条件返回 428；版本已变化返回 412。比较和替换在同一工作区锁内完成，同时写入最多一个成功。
- ETag 不透明，由服务实例、工程、加载标识和 revision 共同确定。不要自行构造。进程重启、重新加载或编辑后的旧 ETag 不能用来覆盖新状态。
- 工程路径 ID 必须与内容 project_id 一致。重新加载采用导入文件中的 revision，并更新加载标识、清空旧计划和撤销历史；加载不是一次可撤销编辑。
- 确认计划使用计划自身绑定的加载标识和版本，不另要求 If-Match。成功提交或撤销推进一版，其他旧计划失效。
- 重复确认、取消后确认及重复撤销返回 409，绝不重复提交或消耗另一条撤销历史。撤销重试必须复用原 request_id。
- 网络中断导致确认结果未知时，先读取工程核对结果。409 需要读取当前工程并重新评估，不能自动生成新计划后再次确认。`retryable=true` 只表示当前失败可考虑重新请求，不表示允许自动批准修改。

## 6. 错误契约

每个产品响应带服务端生成的 `X-Request-ID`，错误体包含相同编号：

```json
{
  "error": {
    "code": "PRECONDITION_FAILED",
    "message": "工程已变化，请重新读取后再保存",
    "request_id": "server-generated-request-id",
    "retryable": false
  }
}
```

调用方按 HTTP 状态和 code 分支；message 用于显示，不能依赖中文字符串判断业务结果。request_id 用于关联具体请求，目前不代表已实现持久化审计日志。

| HTTP | code | 调用方处理 |
|---|---|---|
| 400 | INVALID_REQUEST | 修正 JSON、未知字段或条件请求头 |
| 401 | UNAUTHENTICATED | 获取有效凭据，不信任自报用户 ID |
| 403 | FORBIDDEN | 检查跨站访问方式 |
| 404 | PROJECT_NOT_FOUND / NOT_FOUND | 检查当前用户的工程或接口路径 |
| 405 | METHOD_NOT_ALLOWED | 改用支持的方法 |
| 409 | STATE_CONFLICT | 计划失效、重复处理或无历史；读取当前状态 |
| 412 | PRECONDITION_FAILED | 重新读取工程，避免覆盖其他修改 |
| 413 | PAYLOAD_TOO_LARGE | 请求超过 1 MiB |
| 415 | UNSUPPORTED_MEDIA_TYPE | 使用 application/json |
| 422 | INVALID_PROJECT / PROJECT_ID_MISMATCH | 修正工程及路径 ID |
| 422 | EDIT_REJECTED | 指令解析、模型响应或编辑校验失败；工程未提交 |
| 428 | PRECONDITION_REQUIRED | 添加创建或替换条件头 |
| 500 | PROJECT_ENCODING_FAILED | 检查导出适配器；导出失败未修改工程 |
| 503 | INTEGRATION_DISABLED | 配置产品身份入口 |
| 503 | PROJECT_CAPACITY_EXCEEDED | 工程数达到上限，已有工程不清理；需处理容量 |
| 503 | MODEL_UNAVAILABLE | 配置模型或显式改用离线模式 |
| 503 | MODEL_BUSY | 有界容量已满；可稍后重试预览，响应 Retry-After |
| 504 | MODEL_TIMEOUT | 请求超时，未提交；可重新请求预览 |

同主版本保留已定义错误码的含义，可增加错误码；客户端需要为未知 code 提供通用失败分支。产品接口与旧浏览器接口的错误体不同，不能混用。

## 7. 验证与交付边界

新增 Go 测试覆盖：未配身份时默认拒绝、实际 Bearer 校验、同名工程隔离、自报身份拒绝、跨用户计划拒绝、条件替换及同时写入、旧计划和重复确认保护、组合缩短、撤销、格式适配扩展点、超时错误码、跨站及请求大小限制。原有测试保持通过。

独立编译程序从源码目录之外启动，以随机测试凭据进行真实 HTTP 调用，2026-11-11 已验证 20 项检查，包括产品模式关闭匿名旧接口。该测试不调用真实模型、不代表已接通实际 ToC 产品。后续仍需真实工程样本、产品身份方案及调用方式，完成格式往返和产品端联调后，才能把第 6 阶段整体打勾。

当前产品工程最多 `MAX_SESSIONS` 个运行中工作区（默认 128，按用户与工程组合计数），没有自动清理和持久化。不会因取消 50 人压测目标而取消归属或版本保护，也不以此上限承诺实际并发容量。
# v1.1 扩展补充（2026-11-12）

新增同一身份及工程隔离规则下的 `GET /api/v1/projects/{projectId}/history` 与 `POST /api/v1/projects/{projectId}/redo`。重做请求体为 `{"request_id":"调用者生成的唯一标识"}`；错误码与撤销一致，重复请求拒绝。新编辑清空重做分支；重载清空全部历史。历史只包含实际提交、撤销和重做，不把取消或预览记成执行成功；字段见 OpenAPI 的 History。

消息计划新增 `insert`：`target_id` 是新 ID，`source_id` 是已有片段，另需 `track_id` 和 `start_ms`。按同类型、目标未锁定、无碰撞规则复制，仍须通过原确认接口提交。媒体文件只在浏览器绑定，不进入产品工程数据。新增能力不代表已完成外部编辑器集成。
