# 模型回复格式修复记录

日期：2026-11-11。用户手测反馈：模型回复根节点是数组，Go 将其解码为 ParseResult 对象时失败，页面直接展示 cannot unmarshal array 的内部错误。尚未收到触发该故障的用户原话，因此不将本次验证描述为原始自然语言案例的复测。

## 定位与修复

- 根因：上游返回的 JSON 内容违反固定对象协议。原程序正确拒绝执行，但既没有纠正机会，又直接把解码细节展示给用户，并追加离线句式说明，容易让用户以为是自己表达错误。
- 系统提示明确根节点必须是单个对象。仅当内容 JSON/状态结构校验失败时，最多请求一次格式纠正，保留原始指令、对话和工程快照；不把数组自动包装成可执行计划，不丢弃未知字段，不接纳部分操作。
- 两次请求使用同一个调用上下文，受原有整体超时和并发限制。纠正请求可能额外产生一次模型调用费用。认证失败、限流、网络错误、非正常结束不触发格式纠正。
- 再次不合格时返回用户可理解的提示，说明工程未修改；不显示 Go 内部类型和 JSON 解码错误。模型解析失败不再统一追加离线句式限制。
- 成功纠正后的候选计划仍须经过 Go 引擎检查、预览和明确确认。

## 验证

先用真实 HTTP 模拟上游返回数组，复现与用户相同的错误，再实现修复。回归覆盖：数组后纠正为澄清、数组后纠正为计划仍不提交、连续两次数组拒绝、纠正回复包含非法操作字段仍拒绝、HTTP 429 不重试。每个恢复场景检查导出工程前后相同；校验用户提示不包含内部解码信息和无关离线句式说明。

本轮全量 `go test ./... -count=1`、`go vet ./...` 和构建通过。该回归使用受控上游响应以确定性复现数组错误，不等同于真实云端模型对原始用户输入的复测。
