## 五、本期四个阶段（严格按序，上一阶段验收不通过不进入下一阶段）

### 阶段 1：片段可读化（最小改动，最先做）

1. `Clip` 增加可选 `display_name` 字段（字符串，≤128 字符，可省略），保持 `strictJSON` 兼容与既有必填字段规则
2. 界面展示片段名称 + 可读时间（如「开场镜头 · 0:00–0:05」），内部仍用稳定 ID
3. 示例指令根据当前工程实际片段**动态生成**，移除对固定 `clip-a` 的依赖
4. 工程导入支持 `display_name` 缺省——**旧工程 JSON 必须无条件兼容**

**验收**：加载旧格式 JSON 不报错；带名称工程正常展示；往返导出字段不丢失。

### 阶段 2：自然语言理解增强（本地模拟，不接外部服务）

1. 省略与指代：「这段」「第二个镜头」「刚刚那个字幕」「在两个片段之间」——离线解析器与模型 prompt **两处同步**增强
2. 「在 A 和 B 之间」类位置关系：转换为明确的时间或插入位置语义；**无法确定时澄清，不猜测**
3. 多轮澄清记录已确定信息，**只问剩余缺失项**；用户改口或取消时作废旧意图
4. 否定句与组合句：如「不要删第二段，只把它缩短一秒」只产生 trim 一项

**验收**：覆盖上述表达的本地用例集全部有确定性结果；歧义必澄清；改口不残留旧意图。

### 阶段 3：反馈分层与界面产品化

1. **六种状态区分**：咨询 / 需要补充信息 / 待确认 / 已执行 / 执行失败 / **识别了但当前不支持**（后者必须明说原因，**禁止用建议冒充执行**）
2. 错误信息全部转成用户能懂的中文原因 + 下一步，**禁止直接暴露 JSON 解析错误**
3. 「剪辑助手」单角色入口：悬浮 / 键盘聚焦 / 点击三种方式均可查看功能说明；说明内容与实际能力一致，**不宣传未实现功能**
4. 布局适配右侧窄面板（600px 以内可用），视觉延续浅米白 + 青绿 + 留白
5. 预览卡片用自然语言描述每项修改与受影响对象，**明确说明字幕是否会跟随变化**

**验收**：普通用户无需看文档即可找到支持的功能、看懂修改内容并确认；六种状态各有可复现路径。

### 阶段 4：回归扩充与交付记录

1. 保留任务书全部核心验收（8 个必做场景 + 既有 124 个测试必须继续全绿）
2. 新增回归：素材顺序打乱、重复名称、指代、否定、改口、组合操作、跨工程隔离
3. 更新 README、能力说明、验收报告；清理历史文档中已不适用的外部接入描述
4. 确定性引擎测试与模型测试**分别记录**，不得用少量在线成功案例推导「任意自然语言均支持」

**验收**：`go test ./...` 全绿；新旧用例互不干扰；文档与实现一致。

## 七、安全与工程硬红线（违反任一条即返工）

1. 模型密钥**只放服务端环境变量**，不写入源码、配置文件、前端代码或文档。此前聊天中泄露的两个 key 必须作废，禁止使用

4. **离线无密钥路径必须始终可用**：不设置任何模型环境变量时，`go run .` 与 `go test ./...` 完整可跑（这是验收主路径）
