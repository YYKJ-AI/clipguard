## 2. 业务流程与安全边界

主流程：导入工程 → 展示时间轴 → 输入自由表达 → 模型提出候选计划或澄清需求 → Go 独立定位和校验 → 在工作副本计算预览 → 明确确认 → 校验当前工程状态 → 原子提交 → 根据实际差异报告结果 → 按整条指令撤销。

三种业务结果必须分开：

1. 可执行：目标和参数明确，计算预览并等待确认。
2. 待澄清：目标、参数或指代不明确，列候选或询问缺失信息；补充后重新生成和校验计划。
3. 拒绝：锁轨、非法参数、未知操作等，不修改工程。

自由表达不意味着系统可自行决定剪掉多少。“剪得紧凑一点”等缺少修改量的指令需要澄清。未知文字或模型错误不能被静默忽略。

模型只提供数据，不执行代码、命令或文件操作，不持有直接修改时间轴的工具。用户输入、字幕文字和模型回复均不能绕过 Go 校验及确认。

## 3. 最小架构

本地网页消息入口 → Go 对话协调器 → 可替换解析器 → 计划服务 → Go 编辑引擎 → 工程状态、待确认计划及撤销栈。

网页最小范围：工程导入、轨道与片段列表、消息输入和回复、候选选择、变更预览、确认／取消、撤销，以及“导出工程”下载新 JSON。不做拖拽剪辑器或媒体播放。前端仅负责显示和提交用户操作，核心校验与修改仍由 Go 完成。需在后续设计说明当前工程会话及页面刷新后的行为；关闭页面不等同于重启 Go 程序，不能将二者混淆。

- 模型解析器：经可配置 HTTP 接口调用模型。适配协议等待 Q3 确认，不把 Bifrost 或某家模型写死到编辑引擎。
- 离线解析器：支持公开说明的有限中文句式、组合操作及候选澄清；不依赖外部密钥。
- 模拟解析器：按测试输入返回候选计划、澄清或非法响应，仅用于自动化验证和未配模型时的开发。
- 计划服务：把候选计划绑定到当前工程状态，拒绝未知操作、额外字段和错误类型。
- 编辑引擎：在副本上按操作顺序验证和执行，生成真实字段差异。确认时状态不变才提交相同的候选结果，避免预览与提交脱节。
- 状态管理：project_id、revision，加上导入／切换时更新的加载标识；计划还需唯一标识和状态，拒绝取消、已执行或过期计划。
- 撤销：保存每次实际提交前的业务内容快照，按提交逆序恢复；每次撤销推进版本并使旧计划失效。

不引入微服务、消息队列、向量库或大型 Agent 框架。优先使用 Go 标准库和必要的小型依赖。

## 4. 工程语义建议

以下是实现基线建议，需在最终设计中明确说明；涉及业务偏差时先与用户确认。

- 时间为整数毫秒，区间采用左闭右开；持续时间必须大于零，时间运算检查溢出。
- ID 在工程对应对象集合内唯一，引用必须存在；导入不依赖固定 ID、数组顺序或样例名字。
- 同轨片段不得重叠，不同轨允许重叠；不自动波纹推移。
- 裁剪只修改右端，保持 start_ms 和 source_in_ms 不变；视频素材源区间不可越界。
- 字幕时间调整显式定义起点与时长；修改视频不会自动移动字幕。
- 移动可采用同类型跨轨移动；检查来源与目标轨道锁定，不允许视频移到字幕轨道。
- 相邻两个区间端点相等不属于重叠。
- 一个指令按操作顺序在副本中处理，中间步骤非法也拒绝整个指令；不隐式解决片段互换。
- 模型响应产生期间或用户确认前工程变化，候选计划必须重新生成或重算预览，不能仅再次确认旧预览。
- 每次成功提交与撤销推进版本；预览、澄清、取消、拒绝和重复提交不推进版本。
- 切换或重新导入工程使所有待确认计划失效；建议清空当前撤销栈，避免跨工程撤销。
- 每次撤销一个提交；相同撤销请求重复到达不得消耗另一个历史记录，新的撤销请求可继续撤销更早提交。

## 6. 两天安排与阶段门槛

### 第一天：T0—T4，预算 8 小时

目标：无模型情况下，真实 Go 引擎完成四类操作、多操作原子性、预览确认与撤销；解析接口稳定。

检查点：

- 能导入他人按约定制作、ID 与顺序不同的工程。
- 第二个操作失败，原始工程内容和版本均不变化。
- 取消删除没有状态变化和成功提示。
- 撤销恢复业务内容、推进版本；旧计划不能再次应用。
- 离线路径可输入中文句式并形成计划。

若引擎在第一天末仍未通过核心测试，第二天优先修复；不得用“模型可聊天”替代安全闭环。

### 第二天：T5—T9 与修复缓冲，初步 9—11 小时

目标：网页接通 Go 后端，真实模型完成自由表达与澄清，业务闭环可重复演示，文档及测试齐全。仅要求本地启动，不安排公网部署、域名、服务器或上线流程。

检查点：

- 领导式自由表达能够转为候选计划，或给出必要的澄清。
- 模型输出未知操作、额外字段或非法参数时，独立拒绝。
- 超时、断网、认证失败或不合法响应不会修改工程；明确提示可使用离线句式，不悄悄假装理解了原自由表达。
- 真实模型结果与模拟测试分开记录；没有真实模型不得标记自由表达已验收。
- 从 README 可复现样例与测试。

## 8. 开源复用与 skills 使用

- Bifrost 作为可选外部模型网关使用，不以其源码作为剪辑应用主体，也不要求验收者安装用户本机网关。
- 项目使用可配置模型接口；具体兼容范围以实际联调记录为准。
- 优先标准库；仅为明确需求增加依赖，记录直接复制或修改的源码、来源及许可证。
- 不克隆完整剪辑器或 Agent 模板作为主体；若确需改变这一边界，先确认任务书要求。
- 编码采用测试先行；故障先定位根因；报告通过前实际执行验证。
- 安全审查、GitHub CI 故障处理、PR 评论处理、浏览器验证按需要使用对应本地 skill，不把 skill 当作项目运行依赖。

## 10. 风险与处理

1. 模型晚到：继续实现适配器与模拟测试；真实自由表达验收保持待完成。
2. Go 不熟悉：减少框架与依赖，保持单进程和小模块；不降低核心安全要求。
3. 网关兼容差异：先验证最小请求，再验证结构化响应；不能仅凭“兼容”标签认定功能可用。
4. 模糊语义：优先澄清，不自动猜测剪辑量或目标。
5. 两天不足：优先保留全部安全闭环，及时列出缺项并讨论时间或范围；不把半成品描述成已通过验收。
6. UI 或持久化需求变化：重新估算受影响任务，不无条件沿用 16 小时预算。
