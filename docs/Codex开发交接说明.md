## 二、本期要做什么（四个本地阶段，逐级验收）

### 阶段 1：片段可读化（最小改动，最先做）

1. `Clip` 增加可选 `display_name` 字段（字符串，≤128，可省略），保持 strictJSON 兼容与既有必填字段规则。
2. 界面展示片段名称 + 可读时间（如“开场镜头 · 0:00–0:05”），内部仍用稳定 ID。
3. 示例指令根据当前工程实际片段动态生成，移除对固定 `clip-a` 的依赖。
4. 工程导入支持 `display_name` 缺省（旧工程 JSON 必须无条件兼容）。

验收：加载旧格式 JSON 不报错；带名称工程正常展示；往返导出字段不丢失。

### 阶段 2：自然语言理解增强（本地模拟，不接外部服务）

1. 支持省略与指代表达：“这段”“第二个镜头”“刚刚那个字幕”“在两个片段之间”——在离线解析器与模型 prompt 两处同步增强。
2. “在 A 和 B 之间”类位置关系：转换为明确的时间或插入位置语义；无法确定时澄清，不猜测。
3. 多轮澄清记录已确定信息，只问剩余缺失项；用户改口或取消时作废旧意图。
4. 否定句与组合句覆盖：如“不要删第二段，只把它缩短一秒”只产生 trim 一项。

验收：构造覆盖上述表达的本地用例集，全部有确定性结果；歧义必澄清；改口不残留旧意图。

### 阶段 3：反馈分层与界面产品化

1. 状态区分：咨询 / 需要补充信息 / 待确认 / 已执行 / 执行失败 / **识别了但当前不支持**（后者必须明说原因，禁止用建议冒充执行）。
2. 错误信息全部转成用户能懂的中文原因 + 下一步，禁止直接暴露 JSON 解析错误。
3. “剪辑助手”单角色入口：悬浮/键盘聚焦/点击查看功能说明；说明内容与实际能力一致，不宣传未实现功能。
4. 布局适配右侧窄面板（600px 以内可用），视觉延续浅米白 + 青绿 + 留白。
5. 预览卡片用自然语言描述每项修改与受影响对象，明确说明字幕是否会跟随变化。

验收：普通用户无需看文档即可找到支持的功能、看懂修改内容并确认；六种状态各有可复现路径。

### 阶段 4：回归扩充与交付记录

1. 保留任务书全部核心验收（8 个必做场景、124 个既有测试必须继续全绿）。
2. 新增回归：素材顺序打乱、重复名称、指代、否定、改口、组合操作、跨工程隔离。
3. 更新 README、能力说明、验收报告；清理历史文档中已不适用的外部接入描述。
4. 确定性引擎测试与模型测试分别记录，不得用少量在线成功案例推导“任意自然语言均支持”。

验收：`go test ./...` 全绿；新增用例与旧用例互不干扰；文档与实现一致。

## 三、未来阶段：外部编辑器接入（本期不做，仅记录设计方向）

`product.go` 已预留两个接口，将来接轨时沿插槽实现即可，本期**不写任何实现代码**：

## 四、冻结范围与受控扩展点

**冻结（语义与规则不得改动，修 bug 需单独立项说明）：**
- `engine.go`：`Validate`/`Apply` 校验语义、左闭右开区间、同轨不重叠、trim 只改右端、操作字段白名单。
- `workspace.go`：Binding 机制、revision 推进、整体撤销语义。
- `server.go`：澄清三重失效条件、dialogBinding 隔离、处理期间变化检测。
- `model.go`：system prompt 中已固化的安全规则。

**受控扩展点（允许，须保持向后兼容并补测试）：**
- `Clip` 增加可选 `display_name`（阶段 1）。
- 解析器增加句式与指代规则（阶段 2），不得放宽引擎校验。

## 五、界面要求（web/ 现状为最小实现）

1. 首版只做一个“剪辑助手”角色，无多角色菜单。
2. 悬浮/聚焦/点击查看功能说明；说明与实际能力一致。
3. 面向普通用户：片段名称 + 可读时间，减少裸 ID 和毫秒。
4. 示例指令动态生成。
5. 状态六分层（见阶段 3）。
6. 窄面板适配；浅米白 + 青绿 + 留白。
7. 前端不得绕过后端校验，所有操作仍走计划-确认链路。

## 六、安全与工程红线（违反任一条即返工）

1. 模型密钥只放服务端环境变量，不写入源码、配置文件、前端代码或文档。此前聊天中泄露的两个 key 必须作废，禁止使用。
2. 不执行模型输出的代码或命令；模型只能输出受限 JSON 计划，由 Go 引擎独立校验。禁止 exec/eval 路径。
3. 删除等破坏性操作必须走确认流程，无后门。
4. 离线无密钥路径必须始终可用：不设置任何模型环境变量时 `go run .` 与 `go test ./...` 完整可跑。
5. 不引入无法说明来源的第三方实现；新依赖在 README 列明来源与许可证。
6. 本期不得引入任何对外网络调用作为运行必需依赖（模型模式为可选附加）。
7. 新增代码必须有测试：display_name 兼容性、新句式、指代与改口、状态分层各有负例。

上一版老项目（已接入编辑器的 AI 工作台）的实测反馈见桌面《测试结果.docx》《AI剪辑对话式测试_v2_20261108.xlsx》《测试中暴露的缺失功能清单.docx》。**那是老项目的问题，不是当前代码库的缺陷**；用途是回归约束，不是待修清单。其中可在本地验证的部分：

- 英文提示——界面全中文。
- 测试材料自身错误（D01 预期写反、C06 缺素材、B05 未验证）不归因到 Agent。

需外部编辑器才能验证的部分（画面/音频内容识别、真实素材顺序、平台功能接通）本期不纳入，待接轨阶段再议。
