# 多用户独立工程补充方案

日期：2026-11-10。状态：需求及设计补充，尚未编码、压测。

本文件补充《安全剪辑Agent-任务拆分与验收计划》和《开源选型与节省工时方案》中原先仅单人本机运行的假设；出现冲突时，以本文件的多会话要求为准。原任务计划文件被其他程序占用，未强行覆盖。

## 已确认的业务范围

- 几十人同时使用，每个人编辑自己的工程。
- 不做多人共同编辑同一个工程，不需要协同光标、共享编辑历史或冲突合并。
- 保留网页消息、模型解析、Go 安全编辑、明确确认、撤销和点击导出 JSON 的既定范围。
- GitHub 拉取后可本机启动；多人测试时可由一台电脑启动服务，其他电脑在可达的局域网中访问。是否允许外部访问由启动参数控制，不写死仅回环访问，也不默认开放所有网卡。
- 不增加公网部署、集群或云存储要求。

## 首版架构

单个 Go 服务提供网页及 API，使用服务端会话容纳独立工作区。每个会话拥有独立工程、加载标识、对话上下文、待确认计划及撤销栈。

客户端通过不可预测的会话凭据识别自己的工作区。后端的查询、确认、撤销和导出都先限定到所属会话；请求里提供的 project_id、clip ID 或 plan ID 不能替代归属验证。两个用户导入完全相同的 project_id 和 revision，也必须互不影响。

会话隔离解决本轮的独立工作区要求；它不等同于完整账号登录、跨设备恢复或用户权限管理系统，这些能力当前没有加入范围。

### 状态提交

- 按工作区保护状态，不使用覆盖整个服务的编辑锁。
- 检查会话归属、当前加载标识、project_id、revision 和计划状态，再原子提交。
- 同一工作区的多个页面同时确认时，最多一份基于旧版本的计划成功，其余失效。
- 模型调用前获取必要快照并释放状态锁；返回后再次检查状态，防止长期占锁或应用过期结果。
- 确认和撤销请求具有防重复标识；重复请求不能再次修改或消耗下一条历史。
- 导出读取一致快照，不改变工程内容、版本或其他用户状态。

### 模型调用与资源控制

- 设置模型调用并发上限、请求超时及有界等待，超出容量明确返回繁忙提示。
- 调用上限以领导提供的模型服务额度和实际测试调整，不把网页在线人数直接当作上游允许并发数。
- 不创建无限等待队列，不向客户端无限重试。
- 限制导入文件大小、指令和模型响应长度、对话上下文及历史资源占用。
- 会话寿命、最大会话数、撤销历史上限属于后续配置项。若需要在程序运行期间清理用户会话或截断撤销范围，必须明确用户可见行为，不能静默丢弃工程和历史。

## 新增验收场景

1. 两个会话导入相同项目 ID、版本和片段 ID；一方修改、撤销、重新导入或导出，不影响另一方。
2. 一个会话不能查询、确认、取消、撤销或导出另一个会话的数据。
3. 同一工作区同时确认两份基于同一版本的计划，只发生合法的一次提交。
4. 同一确认或撤销请求并发重复到达，最多产生一次对应状态变化。
5. 模型请求等待期间重新导入或修改工程，返回结果失效，不产生错误修改。
6. 一方模型请求缓慢时，其他工作区仍能查看、确认已有计划、撤销和导出。
7. 模型调用达到配置上限，等待和拒绝行为有界，无无限堆积；失败不改变工程。
8. 以 50 个独立会话作为建议模拟测试规模，记录操作组合、响应时间、错误类型和资源占用；它不是已验证的容量承诺。
9. 真实模型并发按实际额度测试，分别记录网页/API 服务能力和上游模型限制，不能用模拟结果替代真实服务结论。
10. 执行 go test ./...、go build ./...，并在支持的工具链中执行 go test -race ./...；若平台或工具链不支持竞态检测，明确记录，不能标记通过。

## 工期影响

这增加了会话管理、资源控制、并发测试和运行说明的工作。原先 17—19 小时估算不包含完整多用户要求，不能作为当前范围的完成保证。仍以两天为目标，通过减少非必需 UI 效果、依赖和扩展功能控制成本；不得以省时为由共用全局工程、跳过归属校验或只做单用户测试。

模型服务配置尚未提供，不阻塞会话隔离与模拟测试；真实自由表达及上游并发能力保持待验证。
