基础地址为 `http://39.107.68.23:8080/v1`，沿用项目已有 Chat Completions 适配器，无新增网关依赖。测试配置：模型 `dashscope/qwen-plus`、JSON 模式、最大输出 2048 token、整体超时 30 秒，不发送 thinking 参数。密钥仅从进程环境注入，不保存在项目、浏览器或报告中。

重启后如需沿用此网关，在启动终端配置以下环境变量（真实密钥由本机私密输入）：

```powershell
$env:LLM_BASE_URL='http://39.107.68.23:8080/v1'
$env:LLM_MODEL='dashscope/qwen-plus'
$env:LLM_JSON_MODE='true'
$env:LLM_MAX_TOKENS='2048'
$env:MODEL_TIMEOUT_SECONDS='30'
Remove-Item Env:LLM_THINKING -ErrorAction SilentlyContinue
$gatewayCredential=Read-Host '请输入网关密钥' -AsSecureString
$env:LLM_API_KEY=[System.Net.NetworkCredential]::new('', $gatewayCredential).Password
go run .
```

页面默认仍选择离线句式；选择“模型 · 自由表达”后才使用该网关，不自动向多个供应商发送请求。

## 角色与边界

由模型结合职责、当前工程及有限对话历史理解语义，输出固定对象：

| 状态 | 场景 | 行为 |
|---|---|---|
| answer | 剪辑知识、工程内容、工作台用法及能力咨询 | 直接显示回答，禁止携带操作或候选，不改版本和撤销记录 |
| clarify | 编辑请求缺少目标、时间、轨道或修改量 | 追问或给出候选，等待补充 |
| plan | 明确且完整的编辑请求 | Go 独立校验，展示实际预览，用户点击确认后才应用 |
| unsupported | 无关闲聊、一般知识、角色覆盖请求或不支持的编辑能力 | 简短说明限制并引导回剪辑，不追加离线句式错误模板 |

“如何删除”属于咨询，不能生成删除计划。未导入工程也可选择模型咨询；编辑时先引导加载工程，即使模型误报 plan，服务端也会转为无修改的加载说明。已导入工程的旧预览、版本与撤销保护继续有效。

模型只作语义分类和候选生成；Go 强制状态结构及编辑边界。闲聊拒答依赖模型遵循角色，不宣称对所有表达都有确定性分类保证。咨询只保留最近四轮完整问答，不提供长期聊天记忆。已有工程在处理期间变化时，原回复会被拒绝，避免引用过期状态。

模型格式错误最多纠正一次，仍不合法则友好失败；认证、网络、限流不自动重试。两次格式请求共用整体超时，纠正可能产生额外一次模型费用。

## 验证和发现

新增自动化测试先失败后实现：咨询不可带编辑或候选；空咨询拒绝；未导入可咨询；连续多轮上下文受限保留；问答不消耗已有待确认计划和撤销历史；模型误报未导入编辑时不创建工程；模型上下文中的每轨视频顺序不依赖原始 clips 数组排列。

真实网关首轮 15 项通过 13 项，保留 [初测结果](../output/online/gateway-role-acceptance-initial.json)。两项问题：未加载时模型生成计划（Go 已拦截），以及跨轨“第二段”的候选排序有误。修复为服务端加载引导、向模型提供 Go 按起点与 ID 排序的各视频轨片段序列，并明确每轨编号规则。

修复后 [15 项真实端到端测试全部通过](../output/online/gateway-role-acceptance.json)：未导入咨询、未导入编辑引导、闲聊拒答、一般知识拒答、角色覆盖拒答、术语咨询、工程内容咨询、删除方法咨询、否定删除后裁剪、模糊需求追问及补充、多轨候选、四操作组合、锁轨、第二项失败原子性、未知目标。可提交的场景核对预览前不修改、确认结果及整体撤销。
